# N2 · N1 文法 — Interactive JLPT Grammar Textbooks

Two books, one site (switch with the **N2 | N1** buttons in the top bar):

- **N2** — *TRY! 日本語能力試験 N2* (14 chapters, 139 points): https://huangwaylon.github.io/n2/
- **N1** — *TRY! 日本語能力試験 N1* (10 chapters, 123 points), transcribed from the Chinese edition:
  https://huangwaylon.github.io/n2/n1/ — the book's Chinese is not reproduced; all English is ours

GitHub Pages, deployed from `main` /root. Run locally: `python3 -m http.server` then open http://localhost:8000/ (N2)
or http://localhost:8000/n1/ (N1).

## Features

- Every grammar point (plus every ＋Plus sub-pattern and usage note), in the book's order and numbering
- Japanese-first explanations; **English translations and detailed English "deep-dives" are hidden by default**
  — toggle globally with the **EN** switch (or press `E`), or per line with the small **EN** buttons
- Furigana toggle
- Sample texts (見本文), やってみよう practice, Check, and JLPT-format まとめの問題
  (文法形式の判断 · 文の組み立て ★ · 文章の文法 / 読解 · 聴解)
- Listening questions and read-aloud for every example via the browser's Japanese speech synthesis
- Progress ("studied") and scores saved in `localStorage`
- Searchable index, similar-pattern comparison list, can-do list, random drill

Book content (sample texts, explanations, examples, exercises, answer keys, listening scripts) is
transcribed verbatim from the book. English translations of sentences and the deep-dives are supplementary.
In N1 all English is ours (the source is the Chinese edition; its Chinese translations are not reproduced).

## Structure

```
index.html            N2 book page (site root)          n1/index.html   N1 book page
assets/app.js         renderer shared by both books (routing, markup, exercises, TTS, progress); regions [A]/[B]/[C]
assets/css/           base.css (tokens, shared primitives) · shell.css (topbar, sidebar, pages)
                      · content.css (chapter content) · exercises.css (exercises, review) — see docs/LAYOUT.md §3
data/SCHEMA.md        data format (both books)
data/<book>/book.js   book meta: level, counts, translation language, switcher links, footer
data/<book>/chapters/chNN.js   one file per chapter, GENERATED by tools/merge.js from data/<book>/frag/
data/<book>/frag/     transcription fragments (one per chapter part + review) — edit these
data/<book>/compare.js  similar-pattern list · data/<book>/front.js  front matter
docs/N1-TRANSCRIPTION.md  N1 page map, English rules and conventions
tools/books.js        per-book tool config (chapter/point ranges, parts, supplement pages, OCR dirs)
tools/merge.js        fragments → chapter files:  node tools/merge.js n1 5
tools/check.js        structural validator:       node tools/check.js data/n1/chapters/ch05.js
tools/verify-index.js asserts every form in the book's index maps to the right point number (node tools/verify-index.js n1)
tools/<book>/index-manifest.txt  ground truth transcribed from the book's index (N2 pp.216–219, N1 pp.174–177)
tools/<book>/text-baseline.txt   verified text dump (tools/text-snapshot.js)
tools/<book>/ocr/     Vision-framework OCR of every page (tools/ocr/ocr.swift)
tools/ocr-diff.js     fuzzy-matches every transcribed string against the OCR of its pages
tools/zoom.sh         300-dpi strips of a page for reading furigana: tools/zoom.sh n1 17
tools/shot.mjs        screenshot with device emulation (any width, incl. phones); N1 routes are prefixed "n1:"
tools/overflow.mjs    horizontal-overflow / clipping / touch-target probe
tools/text-snapshot.js  text dump of every route; compare against tools/<book>/text-baseline.txt
```

No build step: open `index.html` through any static server (`python3 -m http.server`) or GitHub Pages.
Progress is saved per book in `localStorage`; settings (furigana, EN, speech rate) are shared.

## Verifying content

```sh
for b in n2 n1; do for f in data/$b/chapters/*.js; do node tools/check.js "$f"; done; node tools/verify-index.js $b; done
node tools/ocr-diff.js data/n2/chapters/ch01.js 18-29   # strings below 0.90 need a look at the scan
node tools/ocr-diff.js data/n1/chapters/ch01.js 16-25
for b in n2 n1; do node tools/text-snapshot.js $b | diff tools/$b/text-baseline.txt -; done   # after layout work: no output
```

## Layout tools (screenshots, overflow)

Need Node ≥ 22, Google Chrome, and the site served on port 8765 (`python3 -m http.server 8765`).
Routes are hash routes without `#/` (`""` = home, `ch/1`, `ch/2/review`, `gp/12`, `compare` …).

```sh
# screenshot: ROUTE [WIDTH=1280] [HEIGHT=900] [OUT] [light|dark] [--full] [--en]
node tools/shot.mjs ch/1 390 2400 /tmp/ch1-390.png          # iPhone 14 width, mobile emulation
node tools/shot.mjs ch/2/review 375 900 /tmp/r.png dark --en # dark mode, English layer on
node tools/shot.mjs ch/1 1280 900 /tmp/ch1.png --full        # whole page
# page console messages and JS exceptions are printed to stderr

# overflow probe: ROUTE [WIDTH=390] [--en] [--touch] [--dark]  -> JSON {vw, docW, vp, clip, touch?}
node tools/overflow.mjs ch/1 375
for w in 320 375 390; do node tools/overflow.mjs ch/2/review $w --en; done
node tools/overflow.mjs ch/1 390 --touch                     # also list tap targets < 44×44

node tools/shot.mjs n1:ch/5 390 2400 /tmp/n1c5.png        # N1 book: prefix the route with "n1:"

# layout changes must not change text content:
for b in n2 n1; do node tools/text-snapshot.js $b | diff tools/$b/text-baseline.txt -; done
```

`tools/shot.sh` (plain `--window-size`) only works at ≥ 500 px; for narrower widths it forwards to `tools/shot.mjs`.
